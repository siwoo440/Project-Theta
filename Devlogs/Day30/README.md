# 30일차 - 업적 · 장소 숙련도 · 엔딩 해금 구현

## 이번 일차의 목표

29일차에 판을 없애면서 "계속 플레이할 이유"가 허브 강화(4계열) 하나만 남았다.
강화를 다 사면 목표가 사라지므로, **오래 플레이할수록 열리고 쌓이는 것**을 만들었다.

| 작업 | 내용 |
| --- | --- |
| 업적 | 누적 통계를 목표로 한 업적 23개, 달성 알림, 계약 정기 보상 |
| 장소 숙련도 | 클리어 1 · 3 · 6회마다 ★. 별마다 목표 +5% · 보상 +10% |
| 허브 보강 | 누적 기록 카드 개편, 업적 목록 창, 직전 도전 카드 |
| 엔딩 해금 | 엔딩을 보면 시작 계약 카드 3장 → 4장 |

---

## 기획 결정

### 숙련도는 "어렵게 · 대신 더 크게"

익숙한 장소를 반복하면 쉬워지기만 해서, 별마다 목표 정기를 5% 올리고 계약 정기 보상은 10% 올렸다.
보상 증가폭이 목표 증가폭보다 커야 숙련할 이유가 생긴다(테스트로 고정).

### 엔딩 해금은 새 카드 대신 "카드 1장 더"

새 강화 카드를 추가하면 밸런스 자산(`StageBalance`)의 카드 표도 함께 바꿔야 해서,
**시작 계약에서 제시하는 카드 수를 3장 → 4장**으로 늘리는 해금으로 정했다. 카드 계열이 4개라 4장 모두 다른 계열이 나온다.

### 결과는 지도로 갈 때도 반영되므로 허브는 세션 기억을 본다

결과는 스테이지를 떠날 때 세이브에 반영된다. 지도를 거쳐 허브로 오면 허브에는 "넘겨받을 결과"가 없어 "직전 출격" 카드가 비었다.
`GameSession.LastResult`가 마지막으로 반영한 결과를 기억하고, 허브는 이것을 보여 준다.

## A. 업적 (`Save/AchievementLogic`)

| 종류 | 업적 |
| --- | --- |
| 시작 | 첫 출근(도전 1) · 첫 계약(클리어 1) |
| 클리어 | 단골 손님(10) · 도시의 얼굴(30) |
| 장소 | 도시 산책(4곳) · 도시 정복(8곳) |
| 엔딩 | 루프탑의 밤(1) · 밤의 여왕(3) |
| 최면 · 동행 | 최면 50 / 300 / 1000, 행렬(동행 8명), 되찾은 마음(20) |
| 정기 | 정기 수집가(2000) · 정기의 바다(10000) · 한탕(한 번에 300) |
| 위기 · 성장 | 폭주 조련사 · 힘겨루기 달인 · 카드 수집가 · 완벽주의(S 5회) · 야근 수당(60분) |
| 숙련 | 단골 장소(★3 한 곳) · 도시의 주인(★3 8곳) |

- `SaveDataLogic.ApplyStageResult`가 통계를 더한 뒤 `UnlockNew`로 새 업적을 남기고 보상을 준다. 같은 업적은 한 번만 보상한다.
- `SaveData.UnlockedAchievements`(ID 목록) 추가. 예전 세이브는 빈 목록, 알 수 없는 ID · 중복은 정리한다.
- `PlayStats.SRanks`(S등급 클리어 수)를 새로 센다.
- `GameSession`이 반영 전후 ID 차이로 새 업적을 모아 두고, 지도 · 허브가 `TakeNewAchievements`로 꺼내 알린다.

## 문제와 해결

- **Unity에서 `AchievementDefinition`을 찾지 못하는 오류(6개).**
  Unity가 만든 프로젝트 파일에 `AchievementLogic.cs`만 빠져 있었다. 이 파일의 `.meta`가 이번에 만든 것이 아니라 먼저 있던 오래된 파일이었고,
  Unity가 그 GUID를 예전 자산과 묶어 둔 것으로 보였다. `.meta`를 새 GUID로 다시 만들고 파일을 갱신하자 Unity가 인식했다.
  검증 빌드는 폴더의 `.cs`를 전부 읽어서 이 문제가 드러나지 않았다.
