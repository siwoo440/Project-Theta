# Project θ 개발 일지 — 9일차

## 개발 목표

8일차에 구현한 기본 NPC 소유권·쟁탈·재탈환 시스템을 확장하여, 서로 다른 목적과 행동 템포를 가진 경쟁자 2종을 구성하고 플레이어가 경쟁자의 행동에 직접 개입할 수 있는 힘겨루기 시스템까지 연결했다.

기존 라이벌 명칭은 게임 내에서 **금태양**으로 변경했고, 신규 경쟁자 **인기남**을 추가했다.

9일차의 핵심은 다음과 같다.

```text
Player
↕
금태양
↕
인기남

Neutral NPC까지 포함한 다중 소유권 경쟁
+
플레이어의 직접 개입 수단
```

## 소유권 구조 확장

NPC 소유권을 다음 4종으로 확장했다.

```text
Neutral
Player
Geumtaeyang
PopularGuy
```

게임 내 표시 명칭은 `Geumtaeyang`을 **금태양**, `PopularGuy`를 **인기남**으로 사용한다.

플레이어는 금태양 또는 인기남 소유 NPC 모두 기존 `E / LMB` 최면 입력으로 다시 탈환할 수 있다.

## 금태양 AI 고도화

금태양은 기존처럼 플레이어가 확보한 동행 NPC를 주요 대상으로 삼는다.

단순히 가장 가까운 NPC만 고르는 대신 다음 요소를 이용해 타겟을 평가한다.

- 금태양과의 거리
- 플레이어와 NPC 사이의 거리

플레이어에게서 떨어져 있으면서 금태양이 접근하기 쉬운 NPC가 더 높은 우선순위를 가진다.

기본 추적 수치는 다음과 같다.

| 항목 | 값 |
| --- | ---: |
| 이동 속도 | 4.2 |
| 탐색 거리 | 10 |
| 추적 포기 거리 | 13 |
| 최대 추적 시간 | 5초 |
| 쟁탈 거리 | 1.2 |
| 지배 감소 | 18 / sec |
| 시작 Idle | 0.6~1.5초 |
| 타겟 상실 후 Idle | 0.4~0.9초 |
| 확보 후 Idle | 0.5~1.2초 |

대상이 너무 멀어지거나 최대 추적 시간을 초과하면 해당 NPC를 포기하고 다시 Idle과 Search 과정을 거친다.

## 인기남 추가

새 경쟁자 `인기남_01`을 추가했다.

인기남은 금태양과 달리 **중립 NPC 선점**을 가장 먼저 시도한다.

행동 우선순위는 다음과 같다.

```text
Neutral NPC 존재
→ 가장 가까운 Neutral NPC 접근
→ 거리 1.2 이내
→ 단계형 선점 진행
→ 인기남 소유
→ 인기남 추종 시작

Neutral NPC 없음
→ Player 또는 금태양 소유 NPC 탐색
→ 상대 지배 수치 감소
→ 0
→ 인기남 소유 전환
```

## 인기남 행동 템포

인기남은 금태양보다 느리고 여유 있는 타입으로 조정했다.

최종 수치는 다음과 같다.

| 항목 | 값 |
| --- | ---: |
| 이동 속도 | 2.1 |
| 대상 재탐색 | 0.90초 |
| 추적 포기 거리 | 13 |
| 최대 추적 시간 | 7.5초 |
| 행동 거리 | 1.2 |
| 쟁탈 지배 감소 | 12 / sec |
| 시작 Idle | 1.8~4.5초 |
| 타겟 상실 후 Idle | 1.2~2.7초 |
| 확보 후 Idle | 1.5~3.6초 |

이동 속도는 금태양과 동일한 4.2에서 절반인 2.1로 낮췄다.

또한 행동 대기 시간을 금태양의 2배로 늘려 확실한 템포 차이를 만들었다.

쟁탈 속도 역시 금태양의 18/sec보다 느린 12/sec를 사용한다.

## 인기남 Neutral NPC 단계형 선점

초기 구현에서 인기남은 Neutral NPC에 접근하면 즉시 자신의 소유로 전환했다.

이 방식은 플레이어가 상황을 인지하기도 전에 선점이 끝나 개입 여지가 없었다.

따라서 다음과 같이 세 단계에 걸쳐 선점하도록 변경했다.

```text
접근
↓
띡 / 1⁄3
↓
띡 / 2⁄3
↓
띡 / 3⁄3
↓
인기남 소유
```

각 단계의 기본 간격은 **0.75초**다.

따라서 전체 선점에는 약 **2.25초**가 필요하다.

플레이어는 이 진행도를 확인하고 인기남에게 직접 힘겨루기를 걸거나, 해당 NPC를 먼저 최면해 가져가는 식으로 대응할 수 있다.

## 인기남 선점 진행도 UI

Neutral NPC에 표시되는 진행도를 플레이어 최면과 인기남 선점으로 구분했다.

```text
상단 보라색 게이지
→ 플레이어 Neutral NPC 최면 진행도

하단 청록색 게이지
→ 인기남 Neutral NPC 선점 진행도
```

인기남의 게이지는 연속 증가가 아니라 다음 세 단계로 이동한다.

```text
0
→ 1/3
→ 2/3
→ 3/3
```

인기남이 타겟을 포기하거나 힘겨루기에서 밀려나면 진행 중이던 선점 상태를 초기화한다.

## 인기남 선점 효과음

인기남의 선점 단계가 한 단계 진행될 때마다 짧은 `띡` 효과음을 재생한다.

현재 프로토타입에서는 별도 오디오 파일을 추가하지 않고 런타임에서 짧은 AudioClip을 생성하여 사용한다.

추후 정식 효과음이 준비되면 현재 재생 지점을 그대로 활용해 교체할 수 있다.

## 인기남 Follower 시스템

인기남에게 확보된 NPC는 중립 상태로 돌아가지 않고 인기남을 직접 따라간다.

이를 위해 다음 구조를 추가했다.

```text
PopularGuyFollowerManager
PopularGuyFollowerController
```

인기남도 여러 명의 NPC를 동시에 보유할 수 있다.

플레이어가 인기남 소유 NPC를 탈환하면 인기남 Follower 목록에서 제거된 뒤 Player Follower로 다시 등록된다.

## 금태양과 인기남 간 쟁탈

인기남은 중립 NPC가 모두 소진된 후 자신 소유가 아닌 최면 NPC를 대상으로 삼는다.

따라서 다음 전환이 가능하다.

```text
Player → 금태양
Player → 인기남
금태양 → 인기남
인기남 → Player
금태양 → Player
```

금태양은 현재 플레이어 소유 NPC를 중심으로 행동하며, 인기남은 Neutral 우선 확보 후 다른 세력 NPC를 노리는 차별화된 구조를 가진다.

## 경쟁자 힘겨루기 시스템

금태양 또는 인기남이 NPC 확보 행동을 진행하는 상황에서 플레이어가 해당 경쟁자와 접촉하면 힘겨루기를 시작할 수 있다.

힘겨루기 중에는 중앙 패널이 표시되고 플레이어의 이동, 대시, 최면 입력을 잠근다.

입력 방식은 기존 포획 탈출 미니게임과 동일한 감각을 유지하기 위해 좌·우 마우스 클릭을 번갈아 사용하는 구조로 구현했다.

```text
좌클릭 → 우클릭 → 좌클릭 → 우클릭 ...
```

올바른 교대 입력만 플레이어 쪽으로 힘겨루기 게이지를 이동시키며, 같은 버튼을 연속해서 입력해도 진행도가 증가하지 않는다.

## 힘겨루기 승패 기준

힘겨루기 게이지는 0~100 범위를 사용한다.

초기값은 50이며, 최종 승패 구간은 다음과 같다.

```text
0% ───── 10% │──────── 힘겨루기 영역 ────────│ 90% ───── 100%
             플레이어 패배                    플레이어 승리
```

게이지가 **90% 이상**이 되는 즉시 플레이어 승리, **10% 이하**가 되는 즉시 플레이어 패배로 처리한다.

HUD에는 10%와 90% 위치에 세로 기준선을 표시하여 승패 경계를 바로 확인할 수 있도록 했다.

## 임계값을 넘었는데 종료되지 않던 문제 수정

초기 구현에서는 힘겨루기가 0% 또는 100%까지 도달해야 종료되었다.

또한 플레이어 입력으로 승리 구간에 도달한 프레임에도 상대 압력이 먼저 적용된 뒤 승패를 판정하여, 게이지가 다시 90% 아래로 내려가면서 승리가 누락되는 상황이 발생할 수 있었다.

이를 다음 순서로 수정했다.

```text
플레이어 교대 입력 처리
↓
즉시 10% / 90% 승패 판정
↓
승패 미결정일 경우에만 상대 압력 적용
↓
다시 승패 판정
```

따라서 이제 게이지가 임계선을 넘는 즉시 힘겨루기가 종료된다.

## 힘겨루기 기본 수치

| 항목 | 값 |
| --- | ---: |
| 시작 게이지 | 50 / 100 |
| 올바른 교대 클릭 | +8 |
| 상대 자동 압력 | -10 / sec |
| 플레이어 승리 | 90% 이상 |
| 플레이어 패배 | 10% 이하 |
| 플레이어 패배 피해 | 10 HP |
| 플레이어 기절 | 1.75초 |
| 상대 기절 | 2.5초 |
| 상대 패배 한계 | 3회 |
| 상대 밀려남 거리 | 1.8 |
| 플레이어 밀려남 거리 | 1.6 |

## 플레이어 승리 처리

힘겨루기에서 플레이어가 승리하면 상대를 플레이어 반대 방향으로 밀어낸다.

```text
플레이어 승리
↓
경쟁자 밀려남
↓
패배 횟수 +1
↓
2.5초 기절
↓
Idle / Search 복귀
```

상대별 패배 횟수는 3회까지 누적된다.

```text
● ● ●
↓
● ● ○
↓
● ○ ○
↓
○ ○ ○
```

3번째 패배 시 해당 경쟁자는 필드에서 제거된다.

## 경쟁자 퇴장과 소유 NPC 해제

금태양 또는 인기남이 힘겨루기에서 세 번 패배하면 해당 경쟁자를 필드에서 비활성화한다.

동시에 그 경쟁자가 확보한 NPC도 모두 해제한다.

```text
경쟁자 3회 패배
↓
필드 퇴장
↓
해당 경쟁자의 Follower 목록에서 NPC 제거
↓
NPC Owner = Neutral
↓
최면 수치 = 0
↓
일반 NPC 상태 복귀
```

이를 통해 플레이어는 경쟁자를 직접 제거하여 상대가 누적해서 확보한 NPC 전체를 다시 중립 상태로 돌릴 수 있다.

## 플레이어 패배 처리

힘겨루기 게이지가 10% 이하가 되면 상대가 승리한다.

```text
플레이어 패배
↓
HP -10
↓
상대 반대 방향으로 밀려남
↓
1.75초 기절
```

플레이어 기절 중에는 이동, 대시, 최면, 새로운 힘겨루기 시작을 제한한다.

HP가 0이 되면 기존 Stage 실패 처리를 그대로 사용한다.

## 금태양 힘겨루기 조건

금태양은 Player 소유 NPC를 실제로 쟁탈하는 상황에서 플레이어가 접촉하면 힘겨루기를 시작한다.

```text
금태양
↓
Player NPC 접근 및 Contest
↓
플레이어 접촉
↓
힘겨루기
```

## 인기남 힘겨루기 조건 확장

초기 구현에서는 인기남의 힘겨루기 시작 조건이 너무 좁게 설정되어 있었다.

기존 조건은 다음과 같았다.

```text
State == Contest
TargetMode == Contest
Target Owner == Player
```

이 때문에 인기남이 가장 자주 수행하는 Neutral NPC 선점 중에는 플레이어가 접촉해도 힘겨루기가 시작되지 않았다.

이를 수정하여 인기남이 **NPC 확보 행동을 실제로 수행 중이라면 플레이어가 몸으로 개입할 수 있도록** 조건을 확장했다.

현재 힘겨루기 가능 상태는 다음과 같다.

```text
Neutral NPC를 향해 Approach
Neutral NPC Claiming

Player NPC를 향해 Contest Approach
Player NPC Contest

금태양 NPC를 향해 Contest Approach
금태양 NPC Contest
```

따라서 인기남의 선점을 초반부터 직접 방해할 수 있다.

## 경쟁자 Stunned 상태

금태양과 인기남 모두 힘겨루기 패배 시 `Stunned` 상태로 전환된다.

기절 상태에서는 다음 행동을 중단한다.

- 이동
- 타겟 검색
- NPC 접근
- NPC 쟁탈
- Neutral NPC 선점

기절이 종료된 후에는 이전 타겟을 즉시 이어서 공격하지 않고 Idle 상태를 거쳐 다시 행동한다.

## 인기남 선점 중 힘겨루기 흐름

최종적으로 인기남과의 직접 개입은 다음과 같이 동작한다.

```text
인기남이 Neutral NPC 발견
↓
Approach
↓
1/3 선점
↓
플레이어가 인기남에게 접촉
↓
힘겨루기 패널 표시
↓
좌클릭 ↔ 우클릭 교대
↓
플레이어 승리
↓
인기남 밀려남 + 기절
↓
해당 Neutral NPC 선점 진행도 초기화
```

## 상태 충돌 방지

플레이어 소유 NPC가 다음 상태일 때는 금태양 또는 인기남의 쟁탈 대상에서 제외한다.

- Preparing
- Rampaging
- Capturing
- Recovering

소유권이 실제로 변경될 때는 기존 Follower/Impulse 제어를 정리한 뒤 새 소유자의 Follower 시스템에 등록한다.

이를 통해 하나의 NPC가 Player와 상대 양쪽에 동시에 등록되는 상황을 방지한다.

## Capture 시스템과 힘겨루기 충돌 방지

기존 폭주 NPC 포획 미니게임과 경쟁자 힘겨루기는 동시에 실행되지 않도록 처리했다.

```text
Capture 중
→ 힘겨루기 시작 불가

힘겨루기 중
→ Capture 시작 불가

플레이어 기절 중
→ Capture / 힘겨루기 시작 불가

Stage 종료
→ 진행 중인 힘겨루기 강제 종료
```

두 시스템 모두 좌·우 클릭을 사용하므로 입력 충돌을 방지하기 위한 처리다.

## 타겟 위험 표시

NPC가 금태양 또는 인기남의 현재 타겟으로 지정되면 상태 UI에서 위험 표시를 확인할 수 있도록 연결했다.

소유권 게이지 색상도 각 세력에 맞춰 구분한다.

```text
Player      → 분홍
금태양      → 빨강
인기남      → 청록
```

기존 플레이어 NPC의 충동 경고 UI도 유지한다.

- 힘겨루기 누적 패배 횟수

## 경쟁자 전용 캐릭터 이미지 적용

금태양과 인기남에게 전용 캐릭터 이미지를 추가했다.

리소스 경로는 다음과 같다.

```text
Assets/_Project/Resources/Characters/Geumtaeyang/
Assets/_Project/Resources/Characters/PopularGuy/
```

각 폴더는 현재 런타임 캐릭터 애니메이터 구조에 맞춰 다음 파일을 사용한다.

```text
Idle.png
Move_0.png
Move_1.png
Move_2.png
Move_3.png
```

현재 전용 보행 프레임이 별도로 제작된 상태는 아니므로 동일한 캐릭터 이미지를 각 Move 슬롯에도 사용한다.

금태양과 인기남의 임시 Player Sprite Tint는 제거하고 `Color.white`를 사용해 원본 이미지 색상을 그대로 표시한다.

플레이어는 기존대로 `Characters/Player` 리소스를 사용한다.

## 캐릭터 크기 및 투명 배경 정리

금태양과 인기남 이미지는 플레이어와 비슷한 게임 내 크기로 보이도록 캔버스와 실제 캐릭터 표시 크기를 다시 조정했다.

두 캐릭터 모두 투명 배경 PNG를 사용한다.

## Sprite Import 경고 수정

이미지 교체 과정에서 Unity Console에 다음 경고가 반복 발생했다.

```text
Open Sprite Editor Window to fix 'Move_2_0' not generated
because the rect lies (partially) outside of texture.
```

원인은 이전 이미지의 Sprite Editor 분할 Rect가 `.png.meta`에 남아 있었기 때문이다.

기존 Meta는 다음과 같은 상태였다.

```text
Sprite Mode: Multiple
Idle_0 / Move_0_0 / Move_1_0 / Move_2_0 / Move_3_0
기존 이미지 크기 기준 Sprite Rect
```

이미지 크기가 변경된 뒤에도 이 Rect가 유지되어 새 텍스처 범위를 벗어났다.

최종적으로 금태양·인기남의 총 10개 PNG Meta를 다음 방식으로 정리했다.

```text
Sprite Mode: Multiple
→ Sprite Mode: Single

기존 Sprite Sheet Rect
→ 제거

기존 파일 GUID
→ 유지
```

따라서 런타임 `RuntimeCharacterSpriteAnimator`가 `Resources.Load<Texture2D>`와 `Sprite.Create`를 사용하는 현재 구조에 불필요한 Sprite Editor Slice 정보를 제거했다.

- 금태양이 Player NPC만 쟁탈하는지 확인
- 인기남이 Player·금태양 NPC를 쟁탈할 수 있는지 확인

- 소유권별 인기남 쟁탈 가능 여부 확인

- 금태양 타겟 평가 점수 확인

- 최대 추적 시간 초과 시 포기 확인

- 잘못된 연속 입력 무시

- 90% 이상 즉시 승리

## 9일차 결과

9일차를 기준으로 단일 라이벌과 플레이어 간의 1:1 쟁탈에서 벗어나, **Player·금태양·인기남이 서로 NPC 확보를 경쟁하는 다세력 구조**가 완성되었다.

금태양은 Player 소유 NPC를 직접 빼앗는 공격적인 경쟁자이고, 인기남은 Neutral NPC를 단계적으로 선점하면서 다른 세력 NPC까지 노리는 경쟁자다.

동시에 플레이어가 경쟁자의 행동을 발견하고 몸으로 저지하는 **능동적인 대결 구조**가 추가되어, 단순히 최면 수치를 주고받는 구조를 넘어 확보 타이밍과 개입 판단이 함께 작동하게 되었다.
