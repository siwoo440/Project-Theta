# Project θ 개발 일지 — 2일차

## 개발 목표

1일차에 구축한 프로젝트 기반 위에서 실제 플레이어 이동과 학교 복도형 테스트맵을 구성하고, 이후 NPC·최면 시스템을 올릴 수 있는 2.5D 이동 시험 환경을 완성했다.

## 주요 구현 내용

### 플레이어 2.5D 이동

- WASD 및 방향키 이동 지원
- X축 좌우 이동 + Y축 깊이 이동
- 대각선 입력 정규화로 이동 속도 일정하게 유지
- Rigidbody2D 기반 이동
- 중력 비활성화 및 회전 고정
- Continuous 충돌 감지 적용

### 대시

- Left Shift / Space 입력 지원
- 현재 이동 방향 우선 대시
- 정지 상태에서는 마지막 이동 방향으로 대시
- 기본 대시 속도, 지속 시간, 쿨다운 적용

초기값:

- 일반 이동 속도: 5
- 대시 속도: 11
- 대시 지속 시간: 0.16초
- 대시 쿨다운: 0.6초

### Depth Sorting

- Y 좌표를 기준으로 SpriteRenderer의 sortingOrder 자동 계산
- 화면 아래쪽에 있는 캐릭터가 앞에 렌더링되도록 구성
- 플레이어와 NPC 테스트 오브젝트에 동일한 정렬 방식 적용

### 카메라

- Orthographic Camera 기반
- SmoothDamp를 이용한 부드러운 추적
- X축 중심 추적
- Y축은 완화된 비율로 추적
- 학교 복도 이동 범위에 맞춘 카메라 제한 적용
- 바닥 세로 확장에 맞춰 세로 추적 범위 추가 조정

## 학교 복도 테스트맵

TestStage 실행 시 런타임에서 학교 복도형 테스트 환경이 자동 생성되도록 구성했다.

포함 요소:

- 복도 벽
- 바닥 및 타일 선
- 창문
- 교실 문
- 사물함
- 게시판
- 천장 조명
- 기둥
- 벤치
- 자판기
- 복도 외곽 충돌 경계

벤치와 자판기에는 BoxCollider2D를 적용해 플레이어 이동 및 대시 충돌 테스트가 가능하도록 했다.

## 복도 세로 폭 추가 조정

초기 복도보다 앞뒤 이동 공간이 좁아 보여 바닥의 세로 길이를 약 2배로 확장했다.

변경값:

- 바닥 세로 크기: 4.1 → 8.2
- 이동 가능 최소 Y: -2.15 → -5.2
- 이동 가능 최대 Y: 0.9 유지
- 카메라 세로 추적 비율: 0.35 → 0.5
- 카메라 최소 Y: -1.25

바닥 확장에 맞춰 타일 선, 전면 경계, 좌우 경계 크기와 카메라 이동 범위도 함께 수정했다.

## TestStage 프로토타입

TestStage에서 다음 오브젝트가 자동으로 생성된다.

- Player
- NPC_Placeholder 6개
- RecoveryPointPlaceholder
- Day02_SchoolHallway
- PrototypeHud

현재 NPC는 AI가 없는 Depth Sorting 확인용 임시 오브젝트이며, 실제 NPC AI는 다음 개발 단계에서 구현한다.

## 컴파일 오류 수정

2일차 작업 중 이전 프로토타입 코드가 존재하지 않는 다음 namespace를 참조하면서 컴파일 오류 9개가 발생했다.

- ProjectTheta.Hypnosis
- ProjectTheta.NPC
- ProjectTheta.Stage

2일차 범위에서는 아직 해당 시스템이 필요하지 않으므로 부트스트랩과 HUD에서 해당 의존성을 제거했다.

이후 NPC·최면·스테이지 기능은 각 개발 일차에서 현재 루트 프로젝트 구조에 맞춰 다시 연결한다.
