# 프로젝트 θ UI·캐릭터 아트 전면 교체 설계

---
## 목표

런타임 단색 도형 중심 UI와 서로 다른 화풍의 임시 캐릭터 이미지를 하나의 현대 도시 판타지 2D 아트 방향으로 통일한다. 현재 게임 규칙·저장 데이터·화면 흐름·입력 구조는 유지하면서 공통 UI 스킨, 주요 화면, 주요 캐릭터, 공용 캐릭터, 방해 적 31종을 순차 교체한다.

완료 기준은 다음과 같다.

- 모든 활성 사용자 화면이 공통 UI 스킨을 사용
- 주요 캐릭터 3명의 게임 스프라이트·초상·허브 자세·주요 행동 이미지 적용
- 시민·금태양·인기남 스프라이트 재제작
- 방해 적 31종이 종류별 정식 경로 이미지를 사용
- 모든 캐릭터 스프라이트가 투명 배경·동일 캔버스·동일 발 기준점을 준수
- 이미지 누락 시 기존 색상·도형·레거시 스프라이트로 안전하게 폴백
- 1920×1080 기준 화면과 기존 해상도 대응 유지

---
## 현재 상태

- UI는 40여 개 C# 화면이 `UiFactory`, `UiTheme`, `UiDecor`, `UiOverlay`를 통해 런타임 생성
- 공통 UI 이미지는 최면·커서 일부를 제외하면 대부분 1×1 흰색 스프라이트와 색상 조합
- 정식 주요 캐릭터 경로 `Protagonist`, `Riella`, `Lumia`에는 실제 이미지가 없음
- `Player`, `NPC_Female`, `Geumtaeyang`, `PopularGuy`가 여러 캐릭터와 방해 적의 폴백으로 공유됨
- 신규 `Civilian`은 화풍과 캔버스가 기존 캐릭터와 다르고 배경이 완전히 투명하지 않음
- 방해 적 31종은 정식 경로가 준비되어 있지만 개별 이미지가 없음

---
## 검토한 접근

---
### 접근 A — 공통 스킨과 정식 경로를 먼저 만들고 화면·캐릭터를 단계 적용

공통 UI 스킨과 캐릭터 제작 규격을 먼저 확정한 뒤 모든 화면과 캐릭터를 같은 규칙으로 교체한다. 기존 로직과 레이아웃은 유지하고 표현 계층만 바꾸므로 회귀 위험이 가장 낮다.

---
### 접근 B — 모든 최종 이미지를 먼저 생성한 뒤 일괄 연결

이미지 제작은 빠르게 이어갈 수 있지만 실제 UI 크롭·9-Slice·가독성 문제를 뒤늦게 발견할 가능성이 크다. 캐릭터 31종의 화풍 드리프트도 조기에 잡기 어렵다.

---
### 접근 C — 화면별로 UI와 캐릭터를 함께 완성

플레이 화면 단위 완성도는 빨리 올라가지만 공통 자산이 중복되고 화면마다 규칙이 달라질 위험이 있다.

선택은 접근 A다. 사용자가 요청한 전체 범위를 한 연속 작업으로 처리하되 내부적으로 검증 가능한 단계로 나눈다.

---
## 아트 방향

---
### 캐릭터

- 현대 도시 판타지 2D 애니메이션 일러스트
- 선명한 외곽선과 중간 밀도의 셀 채색
- 보라·금색 마법광과 청록색 보조 강조
- 인게임 스프라이트는 측면 또는 3/4 측면 전신
- 발 아래 중앙 정렬, 1024×1536 공통 캔버스
- 실제 알파 투명 배경, 그림자·후광·글자·소품 배경 제외
- 걷기 프레임은 동일 인물·의상·비율·카메라 유지
- 초상은 허리 또는 가슴 위 크롭, 표정만 변경

---
### UI

- 짙은 자주·남보라 바탕과 얇은 금색 테두리
- 청록색은 집중력·정보, 붉은색은 위험, 녹색은 회복에 한정
- 마도공학 회로와 계약 문양을 낮은 대비 장식으로 사용
- 텍스트가 들어가는 이미지는 게임 로고를 제외하고 만들지 않음
- 패널·버튼은 9-Slice로 재사용하고 상태 변화는 색상·글로우로 처리
- 정보 밀도가 높은 HUD는 장식보다 대비와 숫자 판독성을 우선

---
## UI 구조

---
### 공통 스킨 계층

`UiArtCatalog`가 `Resources/UI/Skin` 주소를 제공하고 `UiSkin`이 로드된 스프라이트와 색상 규칙을 보관한다. `UiFactory`는 기존 API를 유지하면서 패널·버튼·게이지·슬라이더·토글 생성 시 스킨을 자동 적용한다.

기존 화면 코드가 직접 색상을 지정하는 지점은 다음 순서로 정리한다.

1. 공통 팩터리에서 처리 가능한 표현은 `UiFactory`로 이동
2. 화면 의미에 필요한 색상만 `UiTheme` 의미 토큰으로 유지
3. 화면 전용 장식은 해당 화면에서 `UiArtCatalog` 경로로 로드

이미지가 없으면 기존 `UiFactory.WhiteSprite`와 현재 색상을 사용한다.

---
### 공통 UI 자산

- 패널: 기본, 강조, 위험, 툴팁, 토스트, 대화, 결과
- 버튼: 기본, 주요, 위험, 탭, 선택 강조
- 게이지: 공통 트랙, 체력, 집중력, 정기, 충동, 보스, 숙련도, 로딩
- 입력 요소: 토글 켜짐·꺼짐, 체크박스, 슬라이더, 스크롤 손잡이, 키캡
- 장식: 구분선, 이름표, 카드 프레임, 초상 프레임, 선택 글로우, 비네트
- 공통 아이콘: 잠금, 추천, 경고, 목표, 탈출, 층, 시간, 동행자, 보상, 업적
- 시간대 아이콘: 아침, 낮, 저녁, 밤
- 랭크 문양: C, B, A, S

---
### 화면 적용 순서

1. 메인 메뉴·저장 칸
2. 스테이지 HUD·보스 HUD·NPC 상태
3. 대화·프롤로그·스토리·일기장
4. 허브·성장·상호작용
5. 도시 지도·장소 안내
6. 결과·통계·업적·강화 카드
7. 일시정지·설정·조작법·로딩

디버그·성능 패널은 개발 도구로 유지하되 공통 글꼴과 색상 토큰만 적용한다.

---
## 캐릭터 구조

---
### 주요 캐릭터

- 주인공: 게임 스프라이트 5장, 초상 5장, 주요 행동 3장
- 리엘라: 게임 스프라이트 5장, 허브 자세 2장, 초상 8장, 주요 행동 3장
- 르미아: 게임 스프라이트 5장, 초상 8장, 주요 행동 3장

주요 행동은 주인공 `Hypnosis·Victory·Defeat`, 리엘라 `ContractMagic·Victory·Defeat`, 르미아 `ReverseHypnosis·Victory·Defeat`로 제한한다.

---
### 공용 캐릭터

- 일반 시민: `Idle`, `Walk_0~3`
- 금태양: `Idle`, `Walk_0~3`
- 인기남: `Idle`, `Walk_0~3`

기존 `Player`, `NPC_Female`, `Geumtaeyang`, `PopularGuy` 이미지는 즉시 삭제하지 않고 폴백으로 보존한다. 신규 이미지는 정식 경로에 먼저 배치한다.

---
### 방해 적

31개 `DisruptorKind`마다 `Idle`, `Walk_0~3`을 생성한다. 인간형은 같은 캔버스·피벗 규칙을 사용한다. `SecurityCamera`처럼 비인간형인 경우에도 5프레임 주소 계약을 유지하되 움직임·점멸·회전 상태로 프레임을 구성한다.

르미아와 르미아 분신은 주요 캐릭터 정식 이미지를 공유하되 분신은 런타임 색조로 구분한다. 별도 중복 이미지는 만들지 않는다.

---
## 이미지 제작 방식

- 내장 이미지 생성 도구 사용
- 캐릭터별 `Idle`을 기준 이미지로 생성
- 걷기·표정·행동 이미지는 해당 기준 이미지를 참조해 외형 고정
- 각 최종 파일은 프로젝트 `Assets/_Project/Resources` 아래에 저장
- 기존 파일을 직접 덮어쓰기 전에 정식 경로 신규 파일을 우선 사용
- 모든 결과를 육안 확인하고 배경 알파·인물 일관성·잘림·글자·워터마크 검사
- 불합격 결과는 한 항목만 수정해 다시 생성

UI 시안은 `ui-mockup`, 캐릭터는 `stylized-concept`, 투명 스프라이트 보정은 `background-extraction` 분류를 사용한다.

---
## 데이터와 폴백

- 저장 데이터·밸런스·게임 규칙은 변경하지 않음
- `CharacterArtCatalog`와 `WorldArtCatalog`의 정식 경로 우선 규칙 유지
- `RuntimeArtLoader`의 캐시와 월드 높이 정규화 유지
- UI 스킨 누락 시 기존 단색 UI 유지
- 개별 캐릭터 프레임 누락 시 같은 프레임의 기존 경로 사용
- 초상 표정 누락 시 같은 캐릭터 `Default` 사용
- 화면 전용 아이콘 누락 시 텍스트·색상 표시 유지

---
## 테스트와 검증

- UI 카탈로그 경로·폴백 순수 테스트
- `UiFactory` 공통 스킨 적용 EditMode 테스트
- 모든 주요 캐릭터 정식 경로 완전성 테스트
- 방해 적 31종 × 5프레임 경로 완전성 테스트
- PNG 알파·크기·파일 수 검사
- 전체 솔루션 빌드
- `git diff --check`
- Unity EditMode 테스트
- 1920×1080, 1600×900, 1366×768 기준 핵심 화면 육안 점검
- 메인 메뉴→허브→지도→스테이지→결과 흐름 점검

Unity 편집기가 프로젝트를 점유하는 동안에는 사용자 프로세스를 종료하지 않는다. 실행할 수 없는 통합 검증은 개발 기록에 제한으로 남긴다.

## 단계와 커밋 경계

1. 스타일 기준·UI 시안·캐릭터 기준 시트
2. UI 스킨 카탈로그와 공통 팩터리
3. 핵심 UI 화면 적용
4. 주요 캐릭터 적용
5. 허브·지도·결과·시스템 UI 적용
6. 공용 캐릭터 적용
7. 방해 적 지역별 적용
8. 전체 검증·개발 기록·기획서 상태 갱신·푸시

각 단계는 독립 커밋으로 남기며 제목은 `n일차 : 내용` 형식, 본문은 작업 항목별 한 줄로 작성하고 공동작성자는 넣지 않는다. 기존 49~54일차 계획과의 충돌을 피하기 위한 실제 일차 범위와 문서 일정 이동은 실행 계획에서 함께 확정한다.
