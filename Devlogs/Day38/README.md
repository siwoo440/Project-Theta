## 이번 일차의 목표

지금까지는 Unity 안에서만 게임을 돌렸다. 38일차에는 **Unity 없이 켜지는 실행 파일**을 만들 준비를 했다.

- 실행 파일을 만드는 방법이 정해져 있지 않았고, 회사 · 제품 이름도 Unity 기본값(`DefaultCompany` · `Project-Theta`)이었다.
- 가장 무거운 장면(루프탑 클럽 · 심야 추격)이 얼마나 빠르게 도는지 볼 방법이 없었다.
- 확인 목록이 358줄이라 실행 파일로 한 바퀴 돌기 어려웠다.

## A. 빌드 도구 (`Editor/BuildTool`, `Core/BuildInfo`)

새 에디터 전용 어셈블리 `ProjectTheta.Editor`(`Assets/_Project/Editor/`)를 만들었다. 실행 파일에는 들어가지 않는다.

| 메뉴 | 결과 |
| --- | --- |
| `Project Theta/빌드/Windows 실행 파일` | `Builds/Windows/ProjectTheta.exe` |
| `Project Theta/빌드/Windows 개발 빌드 (Profiler 연결)` | `Builds/WindowsDev/ProjectTheta.exe` (F1 디버그 창 · 기록 파일 켜짐) |
| `Project Theta/빌드/빌드 폴더 열기` | 탐색기로 `Builds/` 열기 |

- **빌드 전 확인:** Build Settings에서 켜진 씬을 본다.
  - 첫 씬이 Boot가 아니거나 Boot · MainMenu · Hub · Map · TestStage 중 빠진 씬이 있으면 **빌드하지 않고** 알림 창을 띄운다.
  - 배경음악 · 효과음 파일이 빠졌으면 막지 않고 보고서의 "확인할 것"에만 적는다(대체음이 나오므로).
- **플레이어 설정:** 빌드할 때 제품 이름 · 회사 이름 · 버전을 `BuildInfo` 값으로 맞추고 중복 실행을 막는다.
- **보고서:** 끝나면 출력 폴더에 `build_report.txt`를 남기고 완료 창에도 보여 준다.
  - 시각 · 결과 · 걸린 시간 · 크기 · 경고/오류 수 · 씬 순서 · 확인할 것
- **명령줄 빌드:** Unity를 닫은 상태에서 쓴다.

```
Unity.exe -batchmode -quit -projectPath F:\Project-Theta
  -executeMethod ProjectTheta.EditorTools.BuildTool.BuildReleaseFromCommandLine
  -logFile Builds/unity_build.log
```

- `Builds/`는 원래 `.gitignore`에 있어 커밋되지 않는다.
- 메인 메뉴 맨 아래 줄을 버전 표기로 바꿨다: "v0.38 · 저장 칸 3개 · Esc 일시정지 · F3 성능 표시". 에디터 · 개발 빌드에서는 "v0.38 · 개발 빌드"로 나온다.

## B. F3 성능 표시 (`UI/PerfOverlay`, `Presentation/PerfLogic`)

- 첫 씬 뒤 하나만 만들어져 씬을 넘어 산다. 창은 처음 `F3`을 누를 때 만든다.
- 왼쪽 위 작은 창이고, 클릭을 받지 않아 게임 조작을 가로채지 않는다.

```
FPS 60  ·  16.6 ms
1% 느린 48 FPS  ·  최장 25 ms
GC 2회  ·  메모리 50.0 MB
NPC 24  ·  방해자 3        ← 장소 안에서만
```

- **계산:** 최근 5초의 프레임 시간을 링 버퍼(1,200칸)에 모은다. 글자는 0.25초마다만 다시 쓴다.
  - FPS: 평균 프레임 시간으로 계산한다.
  - 1% 느린 FPS: 가장 느린 1% 프레임의 평균으로 계산한다.
- **색:** 1% 느린 FPS 기준으로 초록 · 노랑(30 미만) · 빨강(20 미만)이다. 창 테두리도 같은 색이다.
- **씬 전환:** 씬이 바뀌면 로딩 프레임이 값을 흐리지 않게 새로 모은다.
- **개발 빌드 기록:** 도전 하나가 끝날 때마다 저장 폴더 `RunLogs/perf_log.txt`에 한 줄을 남긴다.
  - 내용: 장소(심야면 ☾) · 플레이 시간 · 평균 FPS · 최장 프레임 · 끊김(33ms 초과) 횟수 · GC 횟수
  - 카드 · 대사처럼 멈춘 시간과 0.5초가 넘는 튀는 프레임은 뺀다.
- 조작법 창 "화면" 묶음에 "성능 표시 켜기 · 끄기 — F3 (고정)"을 추가했다.

## C. 실행 파일 점검 · 저장 폴더

- **개발용 기능 확인:** 실행 파일에서 막히는 것을 코드로 확인했다.
  - F1 디버그 창과 도전 기록 파일은 `Debug.isDebugBuild`일 때만 켜진다.
  - 자산 저장 · 종료 버튼의 에디터 코드는 `#if UNITY_EDITOR`로 막혀 있다.
  - 실행 중 파일을 읽는 곳은 저장 폴더와 `Resources`뿐이다.
- **설정 창 "저장 폴더" 줄:** 경로를 짧게 보여 주고, `폴더 열기`를 누르면 파일 탐색기로 연다(`SettingsLogic.GetFolderUrl`).
- **저장 폴더 이동 대응:** 회사 · 제품 이름이 바뀌면 Unity 저장 위치도 바뀐다.

| 전 | 후 |
| --- | --- |
| `LocalLow/DefaultCompany/Project-Theta` | `LocalLow/siwoo440/Project Theta` |

- 새 폴더에 설정 · 칸 · 옛 세이브가 하나도 없고 예전 폴더에 있으면, 게임을 켤 때 **한 번 복사**한다(`SaveSystem.CopyOldFolderIfNeeded`). 예전 파일은 지우지 않는다.
- 세이브를 지우고 처음부터 시험하려면 예전 폴더의 세이브도 함께 지워야 다시 복사되지 않는다.
