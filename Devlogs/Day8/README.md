# Project θ 개발 일지 — 8일차

## 개발 목표

7일차까지 완성한 핵심 프로토타입에 라이벌 남성을 추가하고, 플레이어와 라이벌이 최면된 NPC의 소유권을 실제로 빼앗고 되찾을 수 있는 기본 쟁탈 시스템을 구현했다.

8일차 핵심 흐름은 다음과 같다.

```text
플레이어가 NPC 최면
→ Player 소유
→ 라이벌이 대상 탐색
→ 일정 시간 대기
→ 대상에게 접근
→ Player 지배 수치 감소
→ 0 도달
→ Rival 소유로 전환
→ NPC가 라이벌을 따라감
→ 플레이어가 재최면
→ Rival 지배 수치 감소
→ 0 도달
→ 다시 Player 소유
```

## NPC 소유권 구조 추가

NPC의 상태를 단순 최면 여부가 아니라 실제 소유자로 구분하도록 확장했다.

```text
Neutral
Player
Rival
```

소유권은 `NpcOwner`로 관리한다.

중립 NPC는 기존 방식대로 플레이어가 처음 최면하며, 플레이어나 라이벌이 이미 소유한 NPC는 상대가 지배 수치를 0까지 감소시키면 즉시 소유권이 전환된다.

## 공통 지배 수치 기반 쟁탈

플레이어와 라이벌이 별도의 게이지를 가지는 대신 현재 소유자의 지배 수치 하나를 사용한다.

기본 최대 수치는 100이다.

```text
Player / 100
→ 라이벌 쟁탈
→ 100 → 0
→ Rival / 100
```

반대로 플레이어가 라이벌 소유 NPC를 다시 최면하면:

```text
Rival / 100
→ 플레이어 재탈환
→ 100 → 0
→ Player / 100
```

으로 처리한다.

## 라이벌 쟁탈 수치

초기 수치는 다음과 같다.

| 항목 | 값 |
| --- | ---: |
| NPC 지배 수치 최대 | 100 |
| 중립 NPC 플레이어 최면 | +32 / sec |
| 라이벌 쟁탈 감소 | -18 / sec |
| 플레이어 재탈환 감소 | -24 / sec |
| 라이벌 탐색 거리 | 10 |
| 라이벌 이동 속도 | 4.2 |
| 쟁탈 시작 거리 | 1.2 |
| 대상 재탐색 주기 | 0.3초 |

플레이어가 직접 조작해 재탈환하는 행동은 라이벌 자동 쟁탈보다 조금 빠르게 설정했다.

## 라이벌 기본 AI

테스트 스테이지에 `Rival_Male_01`을 추가했다.

현재 전용 라이벌 스프라이트 제작 전이므로 플레이어용 스프라이트를 임시로 사용하고 파란색 Tint를 적용해 구분한다.

라이벌 상태는 다음과 같다.

```text
Idle
→ Search
→ Approach
→ Contest
```

`Search` 상태에서는 플레이어가 현재 데리고 있는 NPC 중 탐색 범위 내 가장 가까운 대상을 찾는다.

대상을 찾으면 `Approach`로 전환하고 대상 NPC의 현재 위치를 계속 추적한다.

쟁탈 거리 안에 들어오면 `Contest` 상태로 전환하여 해당 NPC의 플레이어 지배 수치를 지속적으로 감소시킨다.

## 랜덤 Idle 대기

라이벌이 대상을 발견하자마자 계속 달려드는 느낌을 줄이기 위해 상황별 랜덤 Idle을 추가했다.

최종 조정된 수치는 다음과 같다.

| 상황 | 랜덤 대기 |
| --- | ---: |
| 스테이지 시작 | 0.6~1.5초 |
| 타겟 상실 후 | 0.4~0.9초 |
| NPC 빼앗기 성공 후 | 0.5~1.2초 |

초기 구현에서는 이보다 두 배 긴 시간이 적용되었으나 플레이 템포가 느려져 절반으로 조정했다.

## 라이벌 이동 불가 버그 수정

Idle 기능 추가 후 라이벌이 실제로 움직이지 않는 문제가 발생했다.

원인은 `Search` 상태에서 현재 Target이 없는 상황에도 타겟 유효성 검사를 먼저 수행하던 순서였다.

기존 흐름:

```text
Idle 종료
→ Search
→ Target 없음
→ 유효하지 않은 Target으로 판정
→ 다시 Idle
→ 반복
```

이 때문에 라이벌이 검색 단계에 진입하지 못하고 Idle을 반복했다.

수정 후에는 먼저 현재 Target 존재 여부를 판정한다.

```text
Target 없음
→ Search

Target 존재 + 유효하지 않음
→ 짧은 Idle

Target 존재 + 유효함
→ Approach / Contest 계속
```

이를 위해 `RivalTargetDecisionLogic`을 분리하고 검색·대기·계속 진행 판단을 명시적으로 처리했다.

## 라이벌의 NPC 빼앗기

라이벌이 플레이어 소유 NPC의 지배 수치를 0으로 만들면 다음 순서로 전환한다.

```text
Impulse 상태 정리
→ Player Follower 목록에서 제거
→ Player Follow 종료
→ Owner = Rival
→ 지배 수치 100으로 초기화
→ RivalFollowerManager 등록
→ 라이벌 대열 추종 시작
```

플레이어 Follower와 라이벌 Follower가 동시에 같은 NPC를 제어하지 않도록 소유권 전환 전용 Follow 종료 경로를 추가했다.

## 플레이어 재탈환

기존 최면 입력인 `E` 또는 마우스 좌클릭을 그대로 사용한다.

라이벌 소유 NPC도 플레이어의 최면 대상 후보가 되며 입력을 유지하면 라이벌 지배 수치가 초당 24씩 감소한다.

0이 되는 순간:

```text
RivalFollower 종료
→ 라이벌 보유 목록에서 제거
→ Owner = Player
→ 지배 수치 100
→ FollowerManager 등록
→ 플레이어 추종 재개
```

별도의 재탈환 버튼은 추가하지 않았다.

## 폭주 시스템과 쟁탈 충돌 방지

라이벌은 다음 상태의 플레이어 동행 NPC를 쟁탈 대상으로 잡지 않는다.

- Preparing
- Rampaging
- Capturing
- Recovering

일반적인 `Calm`, `Warning`, `Danger` 상태일 때만 정상적인 쟁탈 대상이 된다.

소유권이 실제로 바뀌는 순간에는 기존 충동·폭주 제어를 취소한 뒤 소유권 이전을 진행한다.

## 라이벌 Follower 시스템

라이벌에게 빼앗긴 NPC는 중립 상태로 돌아가는 것이 아니라 바로 라이벌을 따라간다.

이를 위해 다음 구조를 추가했다.

```text
RivalFollowerManager
RivalFollowerController
```

라이벌도 다수 NPC를 보유할 수 있으며 기본적으로 플레이어의 Compact Formation과 비슷한 다열 형태로 배치된다.

## NPC 소유권 UI

NPC 상태 UI에 소유권 게이지를 추가했다.

```text
Player 소유 → 분홍색
Rival 소유 → 빨간색
```

쟁탈 중에는 현재 소유자의 지배 수치가 실시간으로 감소한다.

기존 충동 게이지는 플레이어 소유 NPC에 한해 계속 별도로 동작한다.

## 스테이지 종료 연동

CLEAR 또는 FAILED 상태가 되면 라이벌 AI와 라이벌에게 소유된 NPC의 추종 동작도 정지하도록 7일차 StageEnd 처리에 연결했다.

따라서 스테이지 종료 후 라이벌만 계속 움직이는 상황을 방지한다.

## 테스트 코드

8일차 기능을 위해 EditMode 테스트용 로직을 추가했다.

`OwnershipContestLogicTests`

- 지배 수치가 시간과 감소율에 맞게 감소하는지 확인
- 수치가 0 아래로 내려가지 않는지 확인
- 플레이어와 라이벌의 쟁탈 가능 소유자 조건 확인

`RivalIdleLogicTests`

- 랜덤 값 0일 때 최소 대기 시간 확인
- 랜덤 값 1일 때 최대 대기 시간 확인
- 랜덤 입력 범위 Clamp 확인

`RivalTargetDecisionLogicTests`

- Target이 없으면 Search로 진행
- 기존 Target이 무효가 되면 Wait 처리
- 유효한 Target은 기존 행동 계속

특히 마지막 테스트는 라이벌이 Target 없이 Idle만 반복하던 문제를 방지하기 위한 회귀 테스트다.

## 8일차 완료 기준

다음 흐름을 기준으로 8일차 시스템을 확인한다.

```text
TestStage 시작
→ 라이벌 랜덤 Idle
→ 플레이어가 일반 NPC 최면
→ 라이벌이 Player 소유 NPC 탐색
→ NPC에게 접근
→ Player 지배 수치 감소
→ 지배 수치 0

→ 플레이어 추종 재개
```

8일차를 기준으로 기존의 단독 NPC 관리 게임플레이에 플레이어와 경쟁하는 외부 세력이 처음 추가되었으며, 이후 라이벌 유형·행동 패턴·쟁탈 고도화의 기반을 마련했다.
