# 15일차 - IMGUI 전면 철거 및 Canvas UI 체계 구축

## 이번 일차의 목표

14일차까지 게임의 모든 화면은 `OnGUI`(IMGUI)로 그려져 있었다.
IMGUI는 에디터 도구용 API라 다음 한계가 뚜렷했다.

- 해상도가 바뀌면 좌표를 직접 다시 계산해야 한다
- 매 프레임 문자열과 `GUIStyle`을 새로 만들어 그린다
- 애니메이션을 주려면 `GUI.matrix`를 직접 밀고 되돌려야 한다
- 색·글꼴·여백이 화면마다 제각각이라 톤을 맞출 수 없다

15일차는 새 기능을 만드는 날이 아니라, **지금까지 만든 기능을 사람이 볼 수 있는 형태로 다시 짓는 날**이다.
게임 로직은 한 줄도 바꾸지 않고 표현층만 교체했다.

## A. UI 프레임워크

`Assets/_Project/Scripts/UI/Framework/`

이 프로젝트는 씬 파일을 비워 두고 런타임에 모든 것을 만든다.
그래서 프리팹 대신 **코드로 uGUI를 조립하는 도구**를 먼저 만들었다.

### UiTheme.cs

화면 전체가 공유하는 색·글자 크기·여백 규칙이다.

| 계열 | 용도 |
| --- | --- |
| `Accent` / `AccentSoft` | 최면·정기를 상징하는 보라 |
| `Gold` | 계약 정기·보상 |
| `Focus` / `FocusExhausted` | 집중력 (고갈 시 탁한 노랑) |
| `Health` / `Danger` | 체력·경고 |
| `Positive` | 안정 상태 |
| `PanelFill` / `PanelEdge` / `RowFill` / `TrackFill` | 패널·행·게이지 바탕 |

기준 해상도는 **1920×1080**. 톤을 바꾸고 싶으면 이 파일만 고치면 된다.

### UiFontProvider.cs

이 프로젝트에는 폰트 자산이 없고, 유니티 내장 폰트(Arial 계열)에는 **한글 글리프가 없다.**
그대로 두면 모든 한국어가 네모(두부)로 보인다.

그래서 OS에 설치된 한글 폰트를 런타임에 빌려 쓴다.

```
Malgun Gothic → 맑은 고딕 → NanumGothic → 나눔고딕
→ Noto Sans KR → Apple SD Gothic Neo → Gulim → Dotum → Batang
```

후보를 하나도 못 찾으면 내장 폰트로 떨어진다. 한글은 깨지지만 **화면은 뜬다.**
폰트 자산을 프로젝트에 넣기 전까지의 임시 방편이다.

### UiFactory.cs

코드로 화면을 조립하는 도구다.

| 함수 | 만드는 것 |
| --- | --- |
| `CreateCanvas` | ScreenSpaceOverlay 캔버스 + CanvasScaler + EventSystem 보장 |
| `CreatePanel` | 테두리 있는 패널 (바깥 이미지 = 테두리, 안쪽 = 채움) |
| `CreateBar` | `Image.Type.Filled` 기반 가로 게이지 (`UiBar`) |
| `CreateButton` | 배경 + 라벨 + 상태색 (`UiButton`) |
| `CreateText` | 한글 폰트가 적용된 라벨 |
| `Stretch` / `Place` / `PlaceRow` | 앵커 배치 도우미 |

#### 캔버스 스케일 정책

```
ScaleWithScreenSize · 1920×1080 기준 · MatchWidthOrHeight 0.5
```

0.5는 가로·세로 변화를 똑같이 반영한다.
창을 세로로 줄여도 글자가 화면 밖으로 밀려나지 않는다.

#### 버튼 색을 역산한 이유

`Button.colors`의 각 상태색은 `targetGraphic`의 색에 **곱해진다.**
바탕이 보라색인데 강조색을 그대로 넣으면 원하는 색이 나오지 않는다.
그래서 `Divide(목표색, 바탕색)`으로 역산한 값을 넣는다.

#### 클릭 가로채기 방지

`CreateImage`가 만드는 이미지는 기본적으로 `raycastTarget = false`다.
장식용 패널·게이지가 클릭을 삼키면 안 되기 때문이다.
클릭을 받아야 하는 **버튼과 가림막에서만** 따로 켠다.

## D. 결과 화면

`Scripts/UI/StageResultPanel.cs` — 전면 재작성

11일차에 만든 **딱-딱-딱 등장 + 랭크 도장** 연출을 그대로 유지했다.
타이밍 계산은 여전히 `StageResultRevealLogic`이 맡고, 이 파일은 그 값을

| 바뀐 것 | 전 | 후 |
| --- | --- | --- |
| 확대 | `GUIUtility.ScaleAroundPivot` + matrix 복원 | `localScale` |
| 페이드 | `GUI.color` 전역 변경 | `Text.color` |
| 미등장 항목 | 매 프레임 스킵 판정 | `SetActive(false)` — 그리지도 않음 |

### 시각 정리

- 총점·계약 정기 줄은 보라 배경을 깔고 글자를 키웠다
- 나머지 줄은 아래에 1px 선만 둬서 표를 읽기 쉽게 했다
- 값은 금색, 항목명은 회색
- 랭크는 패널 **바깥 위쪽**에 걸치게 두어 도장 느낌을 살렸다
- 연출이 끝나야 `허브로` 버튼이 나타난다 (그 전에는 "클릭하면 건너뜁니다")

## E. 인게임 HUD

`Scripts/UI/StageHudView.cs` — 신규

지금까지 플레이어에게 필요한 정보가 개발용 디버그 수치와 뒤섞여 있었다.
**둘을 갈랐다.**

### 배치 원칙

| 위치 | 성격 | 내용 |
| --- | --- | --- |
| 좌상단 | 생존 | 체력 · 집중력 |
| 중상단 | 목표 | 남은 시간 · 정기 게이지 · 상황 안내 |
| 좌하단 | 수단 | 파동 게이지 · 소비 아이템 2슬롯 |
| 중하단 | 자산 | 동행 인원 · 최저 안정도 |
| 우하단 | 보상 | 콤보 |

"지금 뭘 해야 하나"는 위쪽, "뭘 가지고 있나"는 아래쪽에 둔다.

### 색으로 상태를 알리는 곳

- **남은 시간 30초 이하** → 붉게
- **집중력 고갈** → 게이지가 탁한 노랑, 안내문이 붉게
- **최저 안정도** → 초록(>50%) → 금색(>25%) → 빨강 — 폭주 임박
- **파동** → 준비됨(연보라) / 충전 중(보라, 충전률 표시) / 쿨다운(회색, 남은 시간이 차오름)
- **콤보** → 살아 있는 동안 ±2.5%로 아주 약하게 맥동

정기 수치는 게이지 **위에 겹쳐** 적었다. 시선 이동을 줄이기 위해서다.

### 소비 아이템 슬롯

키 번호(1·2)를 어두운 사각형에 넣어 먼저 눈에 들어오게 하고,
그 옆에 이름과 설명을 두 줄로 배치했다.

두 화면 모두 플레이 도중 **화면을 덮는 순간적인 UI**라 표현이 가장 중요했다.

### CaptureHudView

- 포획 중에만 캔버스를 켠다. 평소에는 꺼 두어 그리기 비용이 0이다
- 흔들림(`VisualJoltOffsetX`)은 **가로로만** 준다. 세로로 흔들면 글자를 읽을 수 없다

- 테두리를 빨강으로 둘러 위험 상태임을 알린다

- 게이지 위에 **승·패 임계선을 흰 선으로 표시**했다. 남은 거리가 눈에 보인다
- 게이지 색이 패배선 근처면 빨강, 승리선 근처면 금색, 중간이면 보라
- 왼쪽에 `상대`(빨강), 오른쪽에 `PLAYER`(금색) — 줄다리기 방향을 명시

## 판단한 것

### 1. 게임 로직은 건드리지 않았다

이번 일차에 바뀐 계산식은 **하나도 없다.**
`StageScoreTracker`에 계수기 두 개를 더한 것이 전부이고, 그것도 점수에 관여하지 않는다.
표현층만 갈아끼웠으므로 **밸런스는 14일차와 완전히 동일하다.**

### 2. TextMeshPro 대신 레거시 Text

TMP는 `TMP Essential Resources`를 에디터 메뉴로 임포트해야 하고,
한글을 쓰려면 폰트 아틀라스 자산을 따로 구워야 한다.
자산 없이 코드만으로 돌아가는 현재 구조와 맞지 않아 레거시 `UnityEngine.UI.Text`를 택했다.

폰트 자산을 정식으로 들이는 시점에 TMP로 옮기면 된다.
그때 고칠 곳은 `UiFactory.CreateText` **한 곳뿐**이다.

### 3. LayoutGroup 대신 직접 앵커 배치

`VerticalLayoutGroup` 계열은 편하지만 리빌드 타이밍이 한 프레임 늦고,
코드로 조립할 때는 오히려 결과를 예측하기 어렵다.
모든 요소를 앵커와 크기로 직접 지정했다.
